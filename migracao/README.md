## Arquitetura
```
arquivos exportados ──► Storage "migracao-micrologos" (privado, sa-east-1)
        │                         │  micrologos.py baixar
        ▼                         ▼
   pasta local fora do git (ex.: /home/user/dados-micrologos)
        │  micrologos.py inspecionar   → relatório SEM dados pessoais
        │  micrologos.py carregar      → HTTPS /rest/v1/rpc/migracao_* (só service_role)
        ▼
schema legacy_micrologos (privado, não exposto na API, RLS ligado)
   cargas · bruto_<arquivo> (tudo texto) · mapa_ids · ocorrencias · fusoes_pacientes
        │  transformacoes/NN_*.sql  (funções de limpeza: txt, cpf, cns, telefone, data, valor, status_agenda…)
        ▼
schema public (tabelas do sistema)   + mapa_ids guarda legacy_id ↔ novo uuid
```

- Estrutura criada pela migração `supabase/migrations/0100_migracao_staging.sql` (aplicada em 14/11/2026).
- Nenhuma coluna `legacy_id` nas tabelas do sistema: o de-para fica em `legacy_micrologos.mapa_ids`.
- O schema `legacy_micrologos` pode ser apagado depois da virada e do período de guarda (com aviso à dona).

## Se vier o banco completo (dump)
| Formato | Como abrir |
|---|---|
| `.bak` (SQL Server) | Docker `mcr.microsoft.com/mssql/server` (registro acessível) → `RESTORE DATABASE` → exportar cada tabela em CSV com `bcp`/`sqlcmd` → `carregar` |
| `.fdb`/`.gdb` (Firebird) | Docker `firebirdsql/firebird` ou `apt install firebird3.0-utils` → `isql-fb` → CSV |

| `.dump`/`.backup` (Postgres) | `pg_restore` local (instalado) → CSV |

## Pedidos à sessão de desenvolvimento (enviados em 14/11/2026)
1. **Número do prontuário antigo:** `pacientes.numero_prontuario` é `generated always`; permitir manter o número do Micrologos (`generated by default` + ajuste da sequência depois da carga) ou criar a coluna `prontuario_anterior`.
2. **Auditoria na carga em massa:** fazer `interno.tg_auditoria` ignorar inserções quando `current_setting('app.migracao', true) = 'on'`. Cada carga grava 1 linha-resumo no log, em vez de milhões.
3. **Profissionais antigos sem e-mail:** `profissionais.email` é obrigatório e único. Médicos que saíram ou não têm e-mail precisam entrar como inativos (aceitar e-mail nulo quando `ativo = false`, ou definir uma convenção).
4. **Prontuário histórico (PEP do Micrologos):** o PEP antigo é texto livre e fichas configuráveis, não cabe nas tabelas estruturadas. Sugestão: tabela `prontuario_legado` (paciente, data, profissional, tipo, conteúdo texto/HTML, arquivo PDF, metadados de assinatura digital, legacy_id), só leitura, mostrada na linha do tempo do paciente.
5. **Arquivos do paciente** (laudos PDF, documentos assinados, fotos): bucket privado e tabela de documentos do paciente, com hash SHA-256.
6. **Planos de convênio:** o Micrologos tem convênio → plano. Decidir se o sistema novo terá planos (`convenio_planos`) ou só o convênio.
7. **Agenda histórica:** `agendamentos.profissional_id` é obrigatório. Os médicos antigos entram como profissionais inativos (depende do item 3).
8. Aviso do advisor: `public.abrir_atendimento` é SECURITY DEFINER executável por `authenticated`. Confirmar se é intencional.

### Resposta da sessão de desenvolvimento (14/11/2026)
- Item 7: `abrir_atendimento` como SECURITY DEFINER é intencional (enfermagem abre em nome do médico).
- Itens 1–6 serão aplicados na migração 0008 **depois da aprovação da dona**:
  `pacientes.prontuario_anterior` (ou `generated by default`, se a dona preferir manter o mesmo número),
  `tg_auditoria` ignora as cargas com `app.migracao = 'on'`, e-mail nulo para profissional inativo, `prontuario_legado`,
  `paciente_documentos` + bucket `documentos`, `convenio_planos` + `plano_id` (opcional) em pacientes e agendamentos.
- **Cuidados na carga:**
  - Na carga, rodar `set app.migracao = 'on'`.
  - `atendimentos.agendamento_id` é único (um atendimento por agendamento).
  - O gatilho `tg_bloquear_se_finalizado` impede inserir itens num atendimento finalizado: inserir os itens antes de finalizar, ou usar `prontuario_legado`.
  - O gatilho `horarios_status` preenche horários quando o status muda: na carga, inserir já com os horários históricos.
  - O gatilho `somente_equipe` bloqueia contas de quem não está ativo.
